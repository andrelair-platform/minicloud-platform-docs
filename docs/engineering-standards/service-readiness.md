# Service Readiness Scorecard

> **Self-service answer to "is my repo on the golden path / production-ready?"** — auto-generated from
> every org repo's git tree, never hand-curated. It surfaces the server-side standards (the
> [standardize-new-repo](https://github.com/andrelair-platform/minicloud-gitops/blob/main/.claude/rules/conventions.md)
> baseline + the golden-path delivery signals) as one at-a-glance view. The **5th self-maintaining index**
> on this site, alongside the [Decision Records](./decision-records.md) (ADR), ERD, and traceability indexes.

## How it's scored

Each repo is scored **/8** on presence of the repo-standardization baseline (checked from the committed
git tree — **presence, not quality**: a `tests/` dir proves the repo is *wired* for the layer, not that
coverage is high):

| Criterion | ✅ means |
|---|---|
| **README** | `README.md` at the root |
| **LICENSE** | a `LICENSE` file |
| **CONTRIB** | `CONTRIBUTING.md` |
| **CI** | at least one `.github/workflows/*.yml` |
| **Catalog** | `catalog-info.yaml` (registered in Backstage) |
| **Release** | `release-please-config.json` (automated releases) |
| **Tests** | a `tests/` dir or test files (`*_test.go`, `test_*.py`, `*.spec.ts`, …) |
| **Docs** | an in-repo `docs/` directory |

The **Deploy** column is informational (not part of the /8): **🚀 Kargo** = has `services/<repo>/kargo/`
in minicloud-gitops (full dev→prod promotion), **Helm** = has a wrapper chart but no Kargo, **—** = not a
cluster-deployed service (docs/infra/library repos legitimately show `—`).

:::note Scaffold repos score low by design
A low score on a scaffold (`ktayl-reinsurance`, …) or an infra/library repo is **honest signal**, not a
defect — it shows exactly what's left to standardize. The scorecard exists to make that visible.
:::

The same scoring also drives the **Backstage tech-insights scorecard** on each component's entity page
(both read one source of truth: [`/data/readiness-scorecard.json`](/data/readiness-scorecard.json),
emitted by the generator).
